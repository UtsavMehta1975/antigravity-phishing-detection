    🧠 AI Architecture — 4 Layers
    
          
    Three AI layers + NIST XAI explainability — all working together in one async
            pipeline.
    
          
    
            
    
              
    Layer 1: Random Forest ML Classifier
    
              15 FEATURES · <2ms
            
    
            
    Extracts 15 structural features from every URL:
              Shannon entropy, brand impersonation distance, suspicious TLDs, digit ratios, executable extensions.
              Trained on 2,847 labeled samples. Precision: 94.1%.
    
          
    
          
    
            
    
              
    Layer 2: Computer Vision QR/Quishing Detector
    OPENCV
            
    
            
    Uses cv2.QRCodeDetector with adaptive thresholding to
              extract hidden destination URLs from images, PDFs, and email attachments before a user scans them on their
              phone.
    
          
    
          
    
            
    
              
    Layer 3: Google Gemini LLM + Offline Fallback
    
              HYBRID
                LLM
            
    
            
    When a GEMINI_API_KEY is set, Gemini 1.5 Flash
              analyzes social engineering psychology. When offline: instant heuristic engine (0 latency, 0 cost, 100%
              private). 3-tier fallback: Gemini → Heuristics → Cached Intel.
    
          
    
          
    
            
    
              
    Layer 4: NIST SP 1270 Explainable AI (XAI)
    NIST COMPLIANT
            
    
            
    Replaces opaque risk scores with 4 human-readable
              pillars: Explanation, Meaningfulness, Accuracy, Knowledge Limits. Every verdict explains why
              something was flagged, not just that it was.

    🔒 Security Controls
    
          
    Hardened against real attacks — not just demo-safe.
    
          
    
            
    
              
    ⚡ Rate Limiting
    
              
    15 scans/min, 20 AI queries/min per IP. HTTP 429 +
                Retry-After header. In-memory sliding-window limiter — no Redis needed for demo.
    
            
    
            
    
              
    🛡️ SSRF Guard
    
              
    Blocks RFC 1918 (10.x, 172.16.x, 192.168.x),
                loopback (127.x, localhost), cloud metadata (169.254.169.254), and dangerous schemes (file://, ftp://,
                gopher://).
    
            
    
            
    
              
    🔍 Input Validation
    
              
    URL max 2048 chars. Email max 10MB. Attachment max
                5MB. Extension whitelist enforced server-side. Content validated before any processing.
    
            
    
            
    
              
    🔐 PII Protection
    
              
    Email bodies stored as SHA-256 hashes — never raw
                content. Auto-purge: all scan records deleted after 30 days. URL targets truncated to 200 chars in logs.
              
    
            
    
            
    
              
    📊 Structured Logging
    
              
    JSON log lines with timestamp, level, request_id,
                latency_ms for every scan. Prometheus-compatible /api/metrics/prometheus endpoint for monitoring.
    
            
    
            
    
              
    🔑 No Hardcoded Secrets
    
              
    All API keys (GEMINI_API_KEY) via environment
                variables. Default mode is fully offline — zero external dependencies required to run.

    ❓ Judge Q&A — Basic to Advanced
    
          
    Click any question to see the answer.
    
          
    
            
    Q1: Isn't Gmail / Outlook already doing this?▼
    
            
    Gmail and Outlook catch known spam but have critical blind spots: 1) QR codes
              (Quishing) bypass text-only scanners. 2) Links behind Cloudflare CAPTCHA walls make bots give up and
              falsely mark sites "Clean". 3) They never explain WHY something was blocked. ShieldCheck uses multi-modal
              detection (ML + CV + LLM), handles all 4 evasion types, and gives every user a clear plain-English
              explanation.
    
          
    
          
    
            
    Q2: What is Quishing and why does it matter?▼
    
            
    Quishing = QR Code Phishing. Attackers send an email: "Your MFA session expired —
              scan this QR code on your phone." Corporate computers have firewalls; personal phones don't. ShieldCheck
              uses OpenCV computer vision to extract the hidden URL from QR code images before the user ever picks up
              their phone.
    
          
    
          
    
            
    Q3: How do you scale to 10x / 100x load?▼
    
            
    Verified with load_test.py: 10x (10 concurrent): 2,588ms, 0 errors. 100x
              (/api/scan/batch): 2,685ms for 100 URLs = 26ms/URL avg. Rate limiting correctly throttled 16/20 rapid
              requests. For 1000x: deploy N stateless replicas behind nginx/Cloudflare load balancer — same code, no
              changes needed.
    
          
    
          
    
            
    Q4: What are your security controls?▼
            
    
            
    Rate limiting (HTTP 429), SSRF guard (blocks 192.168.x, 10.x, 127.x, localhost,
              file://, AWS metadata), input validation (URL 2048 char cap, file size limits), PII protection (SHA-256
              hashed bodies, 30-day auto-purge), no hardcoded secrets. All verifiable: submit http://192.168.1.1 to get
              a 422 SSRF Blocked error live.
    
          
    
          
    
            
    Q5: What are the AI model's limitations?▼
    
            
    Honestly: 1) Newly registered domains with no feed history can slip past in first
              24h. 2) Very low-res QR codes may fail OpenCV decode. 3) LLM adds 2-4s when Gemini API is active
              (mitigated by async execution). 4) Multilingual phishing not fully covered. Mitigations: OSINT feed
              correlation, 3-tier fallback (Gemini→Heuristics→Cache), and explicit UNKNOWN_GUARDED state for evasion
              walls.
    
          
    
          
    
            
    Q6: Why a simple mode AND analyst mode?▼
    
            
    The biggest gap in existing tools: they're all built for experts. 90% of phishing
              victims are regular employees, students, or parents — not security analysts. Simple mode gives them a
              yes/no in plain English with 3 action steps. Analyst mode gives SOC teams full forensic data. Same
              backend, same scan, two presentation layers — because accessibility and technical depth shouldn't be
              mutually exclusive.
